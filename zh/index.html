专为现代多协议工程打造

在一个统一工作区内完成可视化调试、AI 智能体工具评估与全自动跨协议端到端测试。

全域 AI 助手与斜杠指令

输入自然语言自动编排多协议流水线与自适应折行排版。支持斜杠快捷指令 (/fix、/explain、/test)、交互式问询 (ask_user)、白名单安全终端工具、全信任自主执行到底与一键节点报错深度自愈。

生命周期三阶段 (Setup / Main / Teardown)

流程原生划分为三大独立子图阶段：Setup 单次执行完成登录预热与变量导出；Main 承载核心业务流（压测时仅循环此阶段，指标纯净）；Teardown 在测试结束后执行资源清理与告警通知，并可直接消费只读 $report 执行报告变量。

交互式流程切片与人机协同 (HITL)

支持在画布上框选任意节点右键「执行选中节点」(run_slice)，自动推导零入度根节点运行而不污染历史执行记录。执行面板原生嵌入交互式卡片 (ask_human)，中途可暂停等待人工确认或输入补充数据。

HTTP Ingress 与 Webhook 模拟服务

在工作流中直接启动内嵌 HTTP 服务监听。http:ingress 节点捕获接收外部 Webhook 推送或 HTTP 回调，下游搭配 http:respond 节点按需构造并返回动态响应，轻松实现端到端回调测试与 Mock 验证。

MCP 智能体服务可视化调试与评估

支持通过 stdio 或 SSE 调试 Model Context Protocol (MCP) 服务器。自动发现工具与 Prompt、串联链式调用，并通过可视化断言评估模型输出准确率。

跨协议端到端集成 (HTTP / WS / TCP / SSE)

原生支持 HTTP、WebSocket、TCP、UDP、SSE、GraphQL 与外部插件（Kafka、Redis 等），彻底打破协议壁垒，消除分散的 Python/Go 脚本。

CI/CD 自动化集成与 JUnit 报告

原生生成标准 JUnit XML 测试报告（--report-format junit --report-file results.xml），每个节点精准映射为测试用例，一键无缝接入 GitHub Actions、GitLab CI 与 Jenkins 流水线。

全局环境解耦与机密安全分层

将环境变量从流程中解耦为独立的全局 YAML 文件（dev.yaml、staging.yaml、prod.yaml），团队共享配置安全入库 Git，私有密钥通过 .local.yaml 覆盖不入库。具备四级变量级联解析与无头 CI 环境管理（mpe env）。

常见问题解答

了解关于 MPE Flow 架构、协议支持与自动化部署的一切信息。

MPE Flow 的内置 AI 助手如何工作？支持本地私有大模型吗？

MPE Flow 内置全域 AI 助手，兼容任意 OpenAI 协议的大模型服务（包括 DeepSeek、OpenAI、Claude、Kimi、通义千问等，或通过 Ollama、vLLM 本地离线部署的私有开源模型）。AI 助手通过 Tool Calling 原生接入画布与执行系统，支持斜杠快捷指令 (/fix、/explain、/test)、交互式选项卡片 (ask_user)、白名单安全终端执行工具与全信任自主执行，并在执行报错时一键诊断与智能自愈，全程 100% 隐私安全。

什么是流程生命周期阶段 (Setup / Main / Teardown)？

MPE Flow 将流程划分为一等公民的三大生命周期阶段：Setup 阶段在运行前单次执行，用于登录预热和全局变量初始化并自动导出到 Main；Main 承载核心业务流（压测时仅并发循环 Main 节点，保证 QPS/P99 指标纯净）；Teardown 在测试后单次执行用于告警通知和资源清理，并注入只读 $report 变量获取测试结果。画布通过左上方切换胶囊栏一键切换三阶段视图，调试器支持跨阶段断点步进。

什么是 MPE Flow？

MPE Flow (Multi-Protocol Flow Executor) 是一款基于 Rust 和 Tauri 构建的高性能跨协议工作流编排与集成测试引擎。它允许开发者通过可视化画布轻松编排跨 HTTP、WebSocket、TCP、UDP、SSE、GraphQL、Kafka 与 MCP 的复杂场景，提供桌面端 GUI 与独立无头 CLI。

内置原生支持哪些协议，哪些协议通过插件扩展？

MPE Flow 单一二进制中原生内置了 7 种核心协议与节点：HTTP/HTTPS（包含客户端请求及内嵌 ingress/respond webhook 模拟服务）、WebSocket、TCP、UDP、SSE (服务端推送事件)、GraphQL、以及 Script/Assertion（脚本与断言）节点。Kafka、MCP、gRPC、Redis、MongoDB、SMTP、IMAP 等其他协议则通过一键侧边进程插件生态提供支持。

MPE Flow 与 Postman 或 JMeter 相比有什么优势？

不同于专注于 HTTP 请求的 Postman，MPE Flow 对长连接与有状态协议（TCP、WebSocket、SSE 流、Kafka 消息队列、MCP 智能体工具）提供一等公民的原生支持，并具备图节点可视化流转、分支路由、变量自动提取、Setup/Main/Teardown 生命周期编排及超高并发压测能力，资源占用极低。

MPE Flow 可以集成到 CI/CD 流水线中吗？

完全可以。MPE Flow 采用单二进制双模式架构，内置独立的 mpe CLI 命令。在 GitHub Actions、GitLab CI、Jenkins 或 Docker 容器中直接执行 mpe run flow.mpf -e staging --report-format junit --report-file results.xml 即可无 GUI 依赖高速运行流程并输出结构化测试报告。

MPE Flow 是开源免费的吗？

是的，MPE Flow 采用宽松的 MIT 开源协议，代码完全托管在 GitHub：github.com/multi-protocol-flow。
